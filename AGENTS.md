# MacShack engineering notes

- **NEVER pass `--remove-existing-content` to `xcrun devicectl device copy to` (or any devicectl command).** It wipes
  the app's entire data container on the device (every game, save, prepared build, log and setting), not just the file
  being copied. To replace a file on the device, copy it, then read it back to check; if it did not change, stop and ask.
  Any command that deletes on the user's device needs their yes first.
- New here? `README.md` (what it is, how to build), then `docs/compat-playbook.md` (how to debug a game) and `docs/compat-status.md` (what runs).
- Keep personal ids (team, bundle id, device ids, /Users paths) out of tracked files: your signing goes in
  `Signing.local.xcconfig` (git-ignored), which overrides `Signing.xcconfig`.
- MacShack runs macOS games on iOS: native arm64 builds, and Intel builds under AArchX. Steam is Valve's macOS client in
  Big Picture. Windows games and Intel games on the real Steam API are not in this repository yet.
- Native on-device prep checks: `python3 host/probe/test_native_prep.py`; transactional installer checks: `python3 host/probe/test_installer.py` (Mac, fake signer). Incoming apps use `Documents/Staging`; installed data uses `Documents/Games`; private signed code uses `Library/Guests`.
- Every host install invalidates prepared games (manifest pins the host executable hash): follow it with `--prepare "<Name>"` per game. Game-specific managed patches are last resorts, live in `prep/patch_<game>_*.py`, verify the original bytes and are idempotent; check: copy the Mac original to a scratch path, run the script twice, expect `patched N site(s)` then `already patched`. Frame/GPU diagnostics (`--shack-watch`, `--shack-gputrace` + `Documents/Logs/gputrace.request`, the per-minute `pacing` line) are described in `docs/compat-playbook.md`.
- Staged game folder check (Mac): `swiftc -parse-as-library host/StagedFolder.swift host/probe/test_staged_folder.swift -o /tmp/t && /tmp/t` (expect `staged folder ok`); libcurl stubs: header of `host/probe/test_curl_stub.c` (simulator).
- Case-insensitive guest paths check (Mac): see the header of `host/probe/test_case_paths.m` (mounts a case-sensitive APFS image).
- Texture and view checks (Mac): `clang -fobjc-arc -DSHACK_BC_TEST shims/AppKit/ShackGLTexture.m shims/AppKit/ShackASTC.c host/probe/test_bc.m -framework Foundation -o /tmp/t && /tmp/t`; the S3TC-to-ASTC transcoder against Arm's reference decoder (`host/probe/test_astc.c`, header lists the astc-encoder build); main-nib parsing `host/probe/test_nib.m`.
- Layer autoresizing check (iOS simulator; Chromium's layer tree): header of `host/probe/test_layer_resize.m`, expect `layer resize ok`.
- JIT script checks: `node host/probe/test_jit_script.js` (Node standard library only).
- Intel games' Steam API under AArchX (Mac, Steam running): header of `prep/aarchx/check_steam_api.c`, expect `steam api ok` with the same hash as Rosetta.
- Shared-home merge check (Mac): `swiftc -parse-as-library host/MergeMove.swift host/probe/test_merge_move.swift -o /tmp/t && /tmp/t` (expect `merge move ok`). Launcher look (simulator): header of `host/probe/test_launcher.swift`.
- Auto-config check (Mac): `swiftc -parse-as-library host/AutoConfig.swift host/probe/test_auto_config.swift -o /tmp/t && /tmp/t`. Launch arguments a game needs (known fixes, log rules) live in `host/AutoConfig.swift`; the phone remembers each game's custom `.args` in `Library/GameConfigs/<bundle id>.args`.
- Steam client setup check (Mac; downloads ~412 MB from Valve once): header of `host/probe/test_steam_setup.swift`, expect `steam setup ok`. New users get Steam from `host/SteamSetup.swift` (onboarding's last page or the first screen's Set up Steam); a Steam copied in by hand (no setup stamp) is never replaced unless someone taps Update or Repair or runs `--steam-setup`.
- App icon parser check (Mac): `swiftc -parse-as-library host/ICNS.swift host/probe/test_icns.swift -o /tmp/t && /tmp/t "<Game.app>/Contents/Resources/<icon>.icns"`.
- Signing fixture checks: `python3 host/probe/test_signing.py --test-zsign` (Mac with pkg-config/OpenSSL; no real key), or `python3 host/probe/test_signing.py --host-app build/Build/Products/Debug-iphoneos/MacShack.app --output /tmp/<new-unique-directory>`. iOS 27 loads a same-team developer-signed dylib outside the app when its **code-signing identifier** matches the installed profile's app bundle identifier; entitlements on the dylib are optional. `codesign --force-library-entitlements` overrides the default omission. The on-device sign/load proof passed twice on iOS 27 (2026-09-26) using the host's one-time imported development .p12; run `--on-device-sign-probe` or the in-app button, then read `Documents/Logs/on-device-signing.log`. ZSign is patched to omit bare-library entitlements, use 16 KB code-signing pages, and signs SHA-256-only; copy signed output to a **new inode before dlopen** or iOS kills dyld on a cached invalid page. Never expose the .p12 or password in logs or source control.
- On-screen controller: touch mapping check in the simulator, header of `host/probe/test_touch_controls.swift`; pad check (Mac, also `xcrun simctl spawn booted` for iOS): `clang -fobjc-arc host/ShackTouchPad.m host/probe/test_touch_pad.m -framework GameController -framework Foundation -o /tmp/t && /tmp/t`.
- Virtual HID gamepad checks (Mac): `clang -fobjc-arc -DSHACK_HID_TEST shims/IOKit/ShackHID.m host/probe/test_shack_hid.m -framework Foundation -framework GameController -o /tmp/t && /tmp/t && SHACK_HID_PAD=xbox2016 /tmp/t` (both pad identities). A shim that fakes a system object must expose exactly the real object's properties and side effects (run loop sources, initial values): guests probe and trust them.
- Memory tier (userspace swap) check (Mac): `clang -Ihost host/ShackSwap.c host/probe/test_swap.c -o /tmp/t && /tmp/t`. Hooks of `new*`/`copy*` selectors must return +1 untouched (`RETAINED` in `host/ShackMetal.m`).
- Objective-C JIT compile check: `xcrun --sdk iphoneos clang -target arm64-apple-ios26.0 -fobjc-arc -fsyntax-only -Wall -Wextra host/ShackJIT.m`.
- Device probes use `--jit-spike --jit-rewrite` or `--jit-spike --jit-alias`; append `--jit-debugger-alloc` to the rewrite probe to test debugger-allocated rather than ordinary mmap pages.
- Built-in JIT: with `Documents/StikJIT/pairingFile.plist` on the phone, launches and `--jit-spike` start the `MacShackJIT` extension (`jithelper/`, StikJIT framework in `vendor/StikJIT`), which runs `host/probe/macshack-jit.js` against MacShack; its log is `Documents/Logs/jit-helper.log`. Without a pairing file, use the script in StikDebug (tap Enable Script). Either way the phone must stay unlocked and LocalDevVPN must be active.
- Stock StikDebug/StikJIT preparation writes `0x69` at each page start; it must not be applied to already-written code without preserving those bytes. The MacShack script reads/writes the existing byte and checks each debugger response.
- `CS_DEBUGGED` is not proof of a live protocol connection or executable memory. Read back VM protections and execute known code. On this iPhone, mprotect can return success while execute permission is stripped.
- Debugger-allocated RX plus a vm_remap RW alias passed 20 rewrites on iPhone 17 Pro Max / iOS 27, including 10 after debugger detach (2026-09-25). This proves the allocator mechanism, not compatibility with Mono's same-address code manager.
- Both tested same-address rewrite paths fail: ordinary RW mmap never acquires X, and debugger-allocated RX loses maximum X when changed to RW (subsequent mprotect RX fails EACCES). A blanket prepare-on-flush hook is not an option.
- Unity Mono is therefore rebuilt from source with `prep/unity-mono/dualmap.patch` (revision from `strings libmonobdwgc-2.0.dylib | grep explicit/`; Silksong = `43035fcf`). Every store into code goes through `mono_codeman_rw ()`; pointers and relocations stay on RX. New code-write sites in Mono must use it too, or they fault on the unwritable RX side (which is how the Mac test catches them). Build: `prep/unity-mono/build.sh <commit>`; the pool comes from `ShackJITPoolSetup` (host) via `SHACK_JIT_POOL`, or `SHACK_JIT_POOL_MB=<n>` for a Mac-only self-made mapping.
- Unknown revisions need no rebuild: `host/ShackTrapJIT.c` replays the stock Mono's stores into the pool (store decoder: STR/STUR/STP/STXR/STLR/CAS/LSE; an unhandled one logs `[ShackTrapJIT] unhandled instruction`). Mac check against a game's shipped runtime: `prep/unity-mono/trapjit/README.md` (expect `stress ok 40038350616`).
- Mac test of the rebuilt runtime: system Mono 6.12 class libs (`MONO_PATH=/Library/Frameworks/Mono.framework/Versions/6.12.0/lib/mono/4.5`, `MONO_CFG_DIR=.../etc`) with `~/src/unity-mono/mono/mini/mono-boehm`; the prefix's `libmono-native-compat.dylib` must point at the arm64 `mono/native/.libs/libmono-native.dylib` (the 6.12 framework's is x86_64 only).
